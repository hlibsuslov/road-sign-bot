# 🇳🇴 Дорожні знаки 2026 — Telegram bot

Telegram-бот для вивчення норвезьких дорожніх знаків ([@roadsigns2026_bot](https://t.me/roadsigns2026_bot)).
Картковий формат (flashcards) із зображеннями знаків, категоріями, темами оформлення
та трекінгом прогресу. Інтерфейс — українською; назви й описи знаків можна вивчати
норвезькою або англійською з перекладом чотирма мовами.

## Можливості

- **Онбординг** — вибір мови вивчення (норвезька / англійська) та мови перекладу.
- **Постійне головне меню** — навчання, статистика, категорії та налаштування завжди
  доступні без ручного введення команд або назв кнопок.
- **Інтервальні повторення (Лейтнер)** — кожен знак проходить рівні 0–6:
  знайомство (картка з описом) → квізи «що означає цей знак?» з 4 варіантами.
  Правильна відповідь піднімає рівень і збільшує інтервал (30 хв → 1 д → 3 д →
  7 д → 14 д → 30 д), помилка повертає знак на початок зі швидким повтором.
  Знак вважається вивченим з рівня 4.
- **Активне пригадування** — перевірка квізом замість пасивного перегляду;
  дистрактори підбираються з тієї ж категорії знаків.
- **Категорії** — вибір груп знаків для вивчення.
- **Статистика** (`/stats`) — прогрес-бар, вивчено / на вивченні / нові,
  точність відповідей, серія днів поспіль, активність за сьогодні,
  розбивка по категоріях.
- **Налаштування** — зміна теми оформлення, мови, скидання прогресу
  (з підтвердженням).
- **Перевірка та нормалізація зображень** — на старті бот валідує файли, виключає відсутні
  картки та зменшує надто великі фото до безпечних для Telegram розмірів.

## Стек

- Python 3.13
- [aiogram](https://docs.aiogram.dev) 3.17 (long-polling, FSM на `MemoryStorage`)
- [Pillow](https://python-pillow.org) — обробка зображень знаків
- SQLite (WAL) — користувачі, розклад повторень, денна статистика;
  версійована схема з автоматичними міграціями (зокрема зі старого формату
  `learned_signs`)

## Структура

```
.
├── bot.py              # хендлери, FSM, точка входу (start_polling)

├── database.py         # SQLite-шар (users, sign_progress, daily_stats, міграції)
├── keyboards.py        # inline / reply клавіатури
├── utils.py            # завантаження знаків, пошук та обробка зображень

│   ├── signs_main.json # основна база знаків
│   ├── signs_extra.json
│   ├── signs_list.txt
│   └── images/         # зображення знаків (*.jpg)
├── Dockerfile          # multi-stage, non-root user `bot`

├── requirements.txt
└── .env.example        # шаблон змінних оточення
```

## Змінні оточення

Скопіюй `.env.example` у `.env` і заповни (див. коментарі у файлі):

| Змінна      | Опис                                              |
|-------------|---------------------------------------------------|
| `BOT_TOKEN` | Токен бота від [@BotFather](https://t.me/BotFather) (обовʼязково) |
| `DB_PATH`   | Шлях до SQLite-файлу (у проді — `/app/db/...` на томі) |

`.env` у `.gitignore` — секрети ніколи не комітяться.

## Запуск через Docker (рекомендовано)

```bash
cp .env.example .env       # і вписати BOT_TOKEN
docker compose up -d --build
docker compose logs -f
```

Особливості compose-стека:

- `build: .` — образ збирається локально (multi-stage, запускається від non-root `bot`).
- `env_file: .env` — змінні передаються в контейнер.
- Том **`bot-db`** змонтований на `/app/db` — база прогресу переживає перебудови.
- Ліміти: `mem_limit: 128m`, `cpus: 0.5`, `pids_limit: 128`.
- `no-new-privileges`, `STOPSIGNAL SIGINT` для коректного завершення polling.
- `autoheal=true` — рестарт контейнера у разі unhealthy (через зовнішній autoheal).

## Локальний запуск (без Docker)

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
export BOT_TOKEN=...    # і за потреби DB_PATH=road_signs_bot.db
python -u bot.py
```

## Перевірка

Тести не використовують справжній Telegram-токен і не надсилають повідомлень:

```bash
python -m unittest discover -s tests -v
```
