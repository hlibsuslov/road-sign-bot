## Платформа: как растёт база вопросов

1. **Схема** (`data/theory/questions.json`): `id`, `topic`, `classes`, `type` (single/multi),
   `difficulty`, `image` (знак или сцена), тексты на no/en/uk/ru, `correct`, `explanation`,
   `source`, `needs_review`. Контракт — `theory.validate()` (тест в CI).
2. **Изображения без отрисовки вручную**: сцена — это данные (`scene`, `you`, `actors`, `signs`,
   `crossing`, `pedestrians`). Следующие шаблоны: светофор, полосы и разметка 1000-й серии,
   обгон на двухполосной, железнодорожный переезд, туннель, гололёд/видимость, мотоцикл в потоке.
3. **Наполнение**: импорт из базы вашего сайта (автошколы и подготовка) — отдельный этап;
   каждая партия проходит `validate`, ревью норвежского текста и снимается с `needs_review`.
4. **Тест-экзамен** станет смешанным (знаки + теория) с распределением по темам как на
   teoriprøven; разделы «личный путь» (автошкола, практика, экзамен) — следующий модуль «Прогресу».

### Этап B. Чат-интерфейс по скиллу telegram-bot-ui

Путь скилла «whole bot»: `references/redesign-orchestration.md` §0–9. Права: A2 (пишем
в репо), мандат M3 (структура меняется), M4 не нужен — все `callback_data` (`q|…`,
`know|…`, `more|…`, `cat_*`, `theme_*`, `lang_*`, `trans_*`, `study_*`, `settings_back`,
`reset_*`) и команды сохраняются.

1. **Исследование и профиль стиля**: `docs/telegram-ui/research.md`,
   `docs/telegram-ui/profile.json` (`tgui.py profile probe|scaffold|check`).
2. **Голосовой гейт** (единственная точка, где нужен твой ответ): главный экран, карточка
   квиза и ошибка — в двух вариантах тона, выбираешь один.
3. **Новая структура** (рекомендация):
   - **Главный экран** — одна карточка, редактируемая на месте: прогресс одной строкой,
     «К повторению: N», кнопки `Вчитися` (primary) · `Повторити N` · `Бібліотека знаків`
     (web_app) · `Статистика` · `Налаштування`. Команды — ярлыки к тем же экранам.
   - **Сессия обучения в одном сообщении**: фото знака меняется через `editMessageMedia`,
     ответ — `editMessageCaption`; чат не засоряется десятками фото. Итог сессии —
     отдельное сообщение («10 знаків · 8 правильно · наступне повторення через 3 год»).
   - **Карточка квиза**: картинка из `data/cutouts` на фоне темы (светлая/тёмная),
     4 варианта, после ответа — правильный подсвечен `style: success`, выбранный неверный
     — понятным текстом (не только цветом).
   - **Reply-клавиатура**: убрать постоянную клавиатуру (её роль берёт главный экран и
     кнопка меню → Mini App). Это убирает «знакомый» элемент — показываю до/после перед
     выкаткой (гейт §6 скилла).
   - **Кнопка меню** (`setChatMenuButton`) → Mini App; описание/короткое описание бота
     на uk/ru/en/no (`setMyDescription`, `setMyShortDescription`).
   - **Ошибки и устаревшие кнопки**: каждая кнопка отвечает `answerCallbackQuery`, старые
     сообщения получают понятный ответ (уже частично есть — довести до всех экранов).
4. **Премиум-эмодзи для навигации** (`commands/emoji.md`):
   - Право: эмодзи на кнопках и в тексте работают, если у владельца бота Telegram Premium
     (для личных чатов) или у бота есть купленный на Fragment username. Каналы — только
     Fragment. Без права Telegram молча вырезает эмодзи без ошибки, поэтому проверка —
     чтение отправленного сообщения обратно.
   - Один набор на весь бот, 8–15 слотов: учиться, повторить, библиотека, статистика,
     настройки, язык, назад, верно, неверно, серия, вивчено, категория.
   - `tgui.py emoji suggest` → выбор пакета (показываю 2 кандидата в светлой и тёмной
     теме) → `emoji resolve` (настоящие id из `getStickerSet`, тестовый токен из env) →
     `IconSystem` в коде с Unicode-фолбэком.
5. **Обновить aiogram 3.30 → 3.34** (поддержка новых полей Bot API), прогнать тесты.
6. **Локализация**: вынести строки в каталог (`locales/uk.json` …), чтобы позже дать
   интерфейс на ru/en/no без правки хендлеров.

Готово, когда: Definition of done из `references/floor.md` для всех экранов, тесты на
старые `callback_data`, `tgui.py check changed` зелёный, скриншоты из реального клиента
(светлая/тёмная тема, iOS/Android/Desktop).

### Этап C. Mini App (база)

Решение по `references/mini-apps/decide.md`: в чате остаётся то, что делается тапами
(обучение, квиз, напоминания); в Mini App уходит то, что требует каталога, поиска,
плотных данных и таймера.

| Экран | Почему Mini App |
|---|---|
| Бібліотека знаків: категории, поиск, фильтр «вивчені / нові / складні» | каталог >10 элементов с фильтрами и поиском |
| Карточка знака: большая картинка, пояснение на 2 языках, похожие знаки, «додати в повторення» | плотный контент, переходы между знаками |
| Прогрес: графики по дням, по категориям, слабые знаки | графики и таблицы шире сообщения |
| Іспит: симуляция теста (таймер, N вопросов, допустимые ошибки, разбор) | таймер, полноэкранный режим, много вопросов за сессию |

Архитектура:
- `webapp/` — Vite + React + TypeScript, сборка в статические файлы; тема и цвета из
  `Telegram.WebApp.themeParams`, кнопки — нативные `MainButton`/`BackButton`, каждый
  вызов WebApp API за проверкой версии (`tgui.py webapp gates`).
- API в том же процессе, что и бот: `aiohttp`-сервер (уже есть в зависимостях aiogram)
  рядом с polling, эндпоинты `/api/signs`, `/api/progress`, `/api/exam`. Каждый запрос
  проверяет `initData` (HMAC от токена бота, срок `auth_date`) на сервере, до чтения
  `user.id`. Статика и картинки (`data/cutouts`) отдаются тем же сервером.
- Общая SQLite: прогресс из Mini App и из чата один и тот же.
- Деплой: тот же контейнер, порт за reverse-proxy с HTTPS на hetzner-8gb; нужен домен
  (решение за тобой, см. §4).
- После действия в Mini App бот сам пишет итог в чат (результат экзамена, напоминание).

Готово, когда: `tgui.py miniapp lint` и `miniapp preview` чистые, проверка `initData`
покрыта тестами (валидная, подделанная, просроченная), Mini App открывается из кнопки
меню в реальном клиенте.

## 3. Алгоритм удаления фона (`tools/cutout.py`)

Исходники — официальная графика: обрезана по краю знака, по контуру тонкая линия, снаружи
формы — чистая бумага (255,255,255), а белый цвет самого знака напечатан чуть серее
(249–252). Отсюда три режима, которые выбираются автоматически:

| Режим | Когда | Что делает | Пример |
|---|---|---|---|
| `flood` | у края картинки белая бумага | заливка «чистого белого» от края с барьером в 1 px вокруг любого нецветного пикселя: белый кант и белое поле знака не трогаются, даже когда контур бледный | треугольники 1xx, круги 3xx/4xx, STOP, ромб 206 |
| `frame+corners` | знак занимает весь кадр | фон не трогается; скругление углов вычисляется по геометрии самого знака: глубина слоя от середины края против глубины того же слоя по диагонали даёт радиус, контур строится концентрично | 502, 521, 548, 601, 612, 723 |
| `full-frame` | заливка «съела» белое внутри знака (полосатые столбики) | откат к прямоугольнику без вырезки, флаг для ручной проверки | 920_H |

Дальше: отброс мелких островков, заливка дыр, уменьшение с премультиплицированной альфой
(без белого ореола на тёмном фоне), обрезка по альфе, WebP lossless. Классификация формы
(треугольник/ромб, круг, восьмиугольник, прямоугольник) пишется в `manifest.json` и
пригодится для Mini App и для дистракторов. Проверка — контактные листы на светлом и
тёмном фоне по всем 293 знакам (`--sheet`).

## 4. Решения, которые нужны от тебя (не блокируют этап A)
